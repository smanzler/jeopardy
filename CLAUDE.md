# jeopardy

Single-package web app: TanStack Start (SSR React 19) with file-based routing, Tailwind v4, and shadcn/ui components built on Base UI. TypeScript throughout, pnpm for packages, Vitest for tests. There is no backend package and no database — everything runs in `src`.

The app is still close to the starter template. `src/routes/index.tsx` is placeholder content and `src/components/ui/button.tsx` is the only UI component so far.

## Layout

| Path                   | Holds                                                      |
| ---------------------- | ---------------------------------------------------------- |
| `src/routes`           | File-based routes. `__root.tsx` is the document shell      |
| `src/components/ui`    | shadcn/ui components (Base UI primitives + `cva` variants) |
| `src/components`       | Cross-route components that are not part of the UI library |
| `src/lib`              | Helpers and configured clients (`utils.ts` holds `cn`)     |
| `src/styles.css`       | Tailwind entry point and the theme tokens                  |
| `src/routeTree.gen.ts` | Generated by TanStack Router. Never edit it                |

## General

- Do not execute `cd` commands into your current working directory
- Write all documentation, including code comments, in ASD-STE100 format

## Writing code

- Read `STYLE.md` and follow the guidelines therein
- Follow DRY (Don't Repeat Yourself) principles: avoid duplicating logic, extract reusable abstractions, and prefer referencing existing code over copying it
- Import with the `@/*` alias, not relative paths that climb out of a directory (`@/components/ui/button`, not `../../components/ui/button`)
- Prefer platform built-ins to 3rd-party libraries (e.g. `fetch` not `axios`, `crypto.randomUUID()` not `uuid`, `Intl.NumberFormat` not a formatting library)
- Add shadcn/ui components with `pnpm dlx shadcn@latest add <component>`. Do not hand-write a component that the registry already supplies. The registry style is `base-nova` and the components import from `@base-ui/react`
- Prettier does not run on commit. Run `pnpm format` after you edit files, and `pnpm check` to see if anything is unformatted
- Avoid flattened type unions discriminated at runtime vs algebraic type unions discriminated at type-check time; e.g.:
  DO:
  type Clue = { type: "text"; prompt: string } | { type: "image"; src: string }
  AVOID:
  type Clue = { prompt?: string; src?: string }

## Verification

- Run `pnpm lint`, `pnpm typecheck` and `pnpm test` before you report the work as complete
- Give `test` a file path to run one test file:

  ```sh
  pnpm test src/lib/score.test.ts
  ```

- Vitest has no config block in `vite.config.ts`, so tests run in the Node environment. A test that renders a component needs `environment: "jsdom"` first — `jsdom` and `@testing-library/react` are already installed
- Use a dev server that already runs when you must see the change. Examples: a UI difference, or a bug that you must reproduce
- Do not start a dev server when `lint` and `typecheck` answer the question
- Check for a dev server on port 3100 before you start one. Stop each dev server that you start

## Commands

| Command          | Effect                     |
| ---------------- | -------------------------- |
| `pnpm dev`       | Dev server on port 3100    |
| `pnpm build`     | Production build           |
| `pnpm preview`   | Serve the production build |
| `pnpm test`      | Vitest, single run         |
| `pnpm lint`      | ESLint (TanStack config)   |
| `pnpm typecheck` | `tsc --noEmit`             |
| `pnpm format`    | Prettier, write            |
| `pnpm check`     | Prettier, check only       |
